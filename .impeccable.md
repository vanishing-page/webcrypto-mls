# Design context

Gathered 2026-08-04. This file is the design brief for the repository.
It is not inferable from the code, which says what was built and not who
it is for.

## Design Context

### Users

Developers evaluating `webcrypto-mls` -- deciding whether to depend on
it. They arrive from the README, open the demo in two browser profiles,
drive it, and then read the source. They are technical but not
necessarily MLS people: they know what end-to-end encryption claims to
be and want to see whether this one holds up against a real server.

The job: decide whether this library is serious. The demo is a
credibility artifact, not a product. It succeeds when a reader comes
away able to say exactly which properties are the protocol's and which
are a trusted server's -- because that distinction is the thing most
E2EE marketing blurs, and being unusually clear about it is the
project's actual claim to trustworthiness.

### Brand personality

Plain, exacting, unflinching.

The prose already has this voice and the visual layer must not soften
it. It says hard things without hedging: "Nothing went wrong. This is
what removal looks like from the inside." It refuses to guess: "Nothing
here can tell you which." It names its own limits: the removal rule "is
a rule of this demo and not of MLS."

Emotional goal is earned confidence, not reassurance. A reader should
trust it *because* it keeps telling them what it cannot do.

### Aesthetic direction

Utilitarian, near-brutalist. Raw but exacting. Trust comes from refusing
to decorate.

Concretely: visible structure, hairline rules instead of cards, square
corners, no drop shadows, no glassmorphism, no gradients. Monospace only
where a value is genuinely machine-generated (room id, epoch, sequence
number, database name) -- never as shorthand for "technical."

Theme is light, and that is a commitment rather than a default. The
governing metaphor is a printed technical document, which is
light-surfaced by nature; inverting it would break the concept. The
audience reads this in daylight beside a README, not in a dark editor.

Anti-references: dashboard UI kits, cards with soft shadows, colored
left-edge accent stripes, "secure = dark mode with a glowing shield."

### Design principles

1. **The page is the log.** The subject is an append-only, numbered,
   partially-readable ledger. Everything renders as a ruled entry in a
   document, and the sequence gutter is the page's signature. Gaps in
   the log are drawn, not hidden.

2. **Structure carries meaning, decoration carries none.** Every rule,
   label and column exists because a distinction in the data needs to be
   visible. Nothing is added to make a block look designed.

3. **Say the limit.** Disclosures are first-class content with their own
   typographic treatment, never small print. What MLS guarantees and
   what the server is trusted for are set as structurally parallel --
   two rows of one ledger -- because presenting one as a reassurance and
   the other as a warning would be an editorial claim the project does
   not make.

4. **Machine values look like machine values.** Ids, epochs, sequence
   numbers and key material get monospace with tabular figures. Prose
   gets a reading face. A reader should never have to wonder which one
   they are looking at.

5. **Never state something the code cannot back.** Contrast ratios are
   computed, not eyeballed. If the page cannot distinguish two cases, it
   says so instead of picking one.

## Typography

No webfonts. Nothing is downloaded to draw this page -- a constraint
the project's own argument makes easy to live with, and one that keeps
the demo's payload honest.

Three registers from stacks already on the machine:

- **Gill Sans** (the stack the other demos already use) -- headings,
  labels, controls. This is where the family resemblance lives.
- **A system old-style serif** (Iowan Old Style / Palatino / Georgia) --
  all prose. What is new here is the split: a paragraph should be
  visibly a different kind of thing from a control.
- **System monospace** -- machine values only, with tabular figures.
  Never used to make prose look technical.

## Palette

Stays in the family with the other demos: the accent is still
`#008aff`. Everything else is expressed in OKLCH at that colour's hue
(253.5) so the neutrals are tinted toward the brand rather than gray.

The one deliberate departure: white text on `#008aff` is 3.45:1 and
fails WCAG AA, so controls that carry white text use `--color-accent-ink`
(5.6:1). `#008aff` itself is kept for non-text marks, where the family
resemblance actually lives.
